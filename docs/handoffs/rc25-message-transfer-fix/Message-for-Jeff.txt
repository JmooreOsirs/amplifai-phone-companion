Jeff — we found and reproduced a fresh-phone collection defect in Mac RC25/build 26101425 (source commit 2f773fff5208c5da6274029b6db92af213ca70aa).

The defect is in StreamedDeviceLink’s filtered-file cleanup. It creates a zero-byte placeholder for a rejected sms.db-journal upload but does not register that placeholder in the SDK’s discarded-file tracker. MobileBackup2 calls cleanup_discarded_files after the transfer, but the unregistered placeholder remains. When the encrypted SMS main database is smaller than its manifest size, the existing compatibility validator sees the leftover journal as an ambiguous sidecar and rejects otherwise valid messages: selected_payload_length / sidecar_present. Contacts and calls can still save, so the result looks partly successful with Messages unavailable.

This is reproduced with the exact RC25 streaming adapter, SDK 10.4.0 selection and cleanup, fictional encrypted data and the installed release’s validation worker/runtime. Control accepts. Uploading a filtered journal leaves the ghost file and rejects. Removing only the proven host-created ghost leaves the ciphertext and manifest unchanged and accepts again. The installed helper matches RC25 source; a stale binary is not the explanation for this reproduced condition.

Other testers can encounter this condition. We cannot truthfully say it caused the exact October 15 owner run: that attempt’s detailed optional-source diagnostic was discarded after the successful contacts/calls save. The older saved-backup success is not fresh-transfer acceptance.

Please apply fix-filtered-journal-placeholders.patch against the matching RC25 source, review and run its self-contained regressions, then rebuild/sign/notarize a new Mac release. The patch must remove only bounded, identity-verified placeholders created by this host for filtered selected-source journals, after the real Backup request has successfully completed. Preserve protocol readback, moves/copies/removals/replacements, genuine selected sidecars, manifest-listed sidecars, nonempty/replaced/untracked files, and all existing encryption/digest/copy/integrity validation. Do not simply ignore zero-byte journals, disable WAL checks, or restore an unbounded discarded-file set.
